Lab guide 5

Boot, Targets, Services, and Recovery

Control services and boot targets, and - most importantly - recover a system you have locked yourself out of. This is the lab that saves you in the exam.

3-4 hours Week 4 complete
Before you start
  • Week 4 complete
  • Console access to the VM, not just SSH
  • Use a VM console for network, boot and storage changes. Commands are guest commands, not macOS commands.
  • Examples use shea; substitute your configured account consistently. Follow the weeks in order; shell variables must be recreated after reboot.
  • Take a snapshot of both machines. You will break things on purpose.

1. Services: started versus enabled

These are two separate things, and confusing them is the classic way to lose marks after a reboot.

The full lifecycle
sudo systemctl status sshd --no-pager
sudo systemctl stop sshd
sudo systemctl start sshd
sudo systemctl restart sshd
sudo systemctl reload sshd
Enable is about boot, start is about now
systemctl is-active sshd
systemctl is-enabled sshd
sudo systemctl disable sshd
systemctl is-enabled sshd
sudo systemctl enable --now sshd
What is running, and what failed
systemctl list-units --type=service --state=running | head
systemctl --failed
Worth knowing

'enable --now' does both in one command. If a task says a service must be running and must come back after reboot, that is the command you want.

2. Boot targets

See and switch at runtime
systemctl get-default
systemctl list-units --type=target
sudo systemctl isolate multi-user.target
Set the default permanently
sudo systemctl set-default multi-user.target
systemctl get-default
ls -l /etc/systemd/system/default.target

3. Interrupt the boot process

Do this from the VM console, not over SSH. Take a snapshot first.

At the GRUB menu
# At GRUB press e; on the linux line replace the standalone ro with rw.
# Remove any rd.break argument and append: init=/bin/bash enforcing=0
# Ctrl-X boots with this temporary change. Use the VM console.
In the emergency shell, remount and enter the real root
# init=/bin/bash already uses the installed root filesystem at /
mount -o remount,rw /
Reset the root password and force an SELinux relabel
passwd root
touch /.autorelabel
sync
exec /sbin/init
# Wait for relabeling and normal boot; then boot normally and verify enforcing.
Worth knowing

RHEL/Rocky 10 initramfs may lack chroot and rd.break may require authentication. Do not mix /sysroot and / recovery environments. enforcing=0 is temporary; keep SELINUX=enforcing in the installed config. See Red Hat solution 7121729.

4. Boot into a different target manually

A one-time change at the GRUB menu, useful when a service is preventing a normal boot.

Append a target to the kernel line
# At the GRUB menu, press 'e' and append one of these to the 'linux' line:
#   systemd.unit=rescue.target
#   systemd.unit=emergency.target
#   systemd.unit=multi-user.target
# Then Ctrl-X to boot. The change applies to this boot only.

5. Modify the bootloader

Change the GRUB menu timeout, rebuild and inspect the generated configuration. This is not a kernel argument.

Edit the defaults and rebuild
sudo cp /etc/default/grub /root/grub.backup
sudo grep GRUB_TIMEOUT /etc/default/grub
sudo sed -i 's/^GRUB_TIMEOUT=.*/GRUB_TIMEOUT=10/' /etc/default/grub
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
Confirm the change landed
sudo grep -nE 'timeout_style|set timeout=' /boot/grub2/grub.cfg
sudo grub2-editenv list
# If menu_auto_hide is enabled and the menu must be visible:
# sudo grub2-editenv - unset menu_auto_hide
# Verify the actual menu at the next reboot.

6. Kernel argument round trip

Use a disposable argument, inspect it after a normal reboot, then remove it.

Add and inspect
sudo grubby --update-kernel=ALL --args=rhcsa_lab=1
sudo grubby --info=ALL | head -30
# Reboot normally, then: cat /proc/cmdline
# Remove after verification:
# sudo grubby --update-kernel=ALL --remove-args=rhcsa_lab=1

Verify your work

Run these before you consider the lab finished.

  1. systemctl get-default
  2. systemctl is-enabled sshd && systemctl is-active sshd
  3. grep GRUB_TIMEOUT /etc/default/grub
  4. reboot, then re-run all three and confirm nothing changed
Break it, then fix it

Break:

sudo systemctl disable sshd && sudo reboot

What you'll see: After the reboot you cannot SSH in at all. The service exists and works, but nothing started it.

Fix:

From the VM console: sudo systemctl enable --now sshd

Why it matters: This is the reboot-persistence rule made concrete. In the exam a task like 'ensure the web service is running' almost always means running now AND enabled at boot. Get in the habit of typing 'enable --now' rather than 'start'.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Check every persistent configuration after a normal boot. This is our practice validation, not an assertion about official exam scoring. Fix it now, while you can still see what you did.
